# 第 06 课自测题答案

> 建议先自己做题，再展开本页。

## 1. 为什么 `hash(vec2 p)` 用位置 `p` 做输入，而不是直接用 `uTime`？若每帧对同一像素用 `rand()` 式随机，画面会怎样？

**噪声需要「空间上连续、时间上可控」**。`hash(p)` 保证：**同一 UV 位置** 每次算出相同值，相邻格点插值后形成平滑过渡；再用 `uTime` 去 **偏移或扭曲采样坐标**，图案才会流动。

若每帧对同一像素独立随机（例如 `hash(p + uTime)` 且不做插值、或 CPU 侧真随机），值会在时间上剧烈跳变，得到 **电视雪花 / 静态噪点**，而不是云、火焰等 **连贯** 的程序化纹理。

## 2. `fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453)` 与从 `sampler2D` 读取预烘焙噪声图，各有什么优缺点？

| 方式 | 优点 | 缺点 |
|------|------|------|
| **`fract(sin(dot))` hash** | 无纹理依赖、体积小、易教学、可任意缩放 UV | 质量一般、大尺度可能有带状伪影、高质量需更多 octave 或更好算法 |
| **纹理噪声** | 可存 Perlin/Simplex 等高质量数据、采样快、易多层混合 | 需上传资源、重复周期受贴图尺寸限制、缩放过大可能模糊 |

本课用 hash 是为了理解 **「噪声 = 空间函数」**；生产环境常用预计算或更复杂的过程噪声（如 Simplex）。

## 3. fBm 里每层 `p *= 2.0` 且 `amplitude *= 0.5` 分别起什么作用？

- **`p *= 2.0`**：频率加倍，采样更密的格点，叠加 **更细的细节**。
- **`amplitude *= 0.5`**：减弱高频层的权重，避免细节盖过整体形状，符合自然界「大形强、小纹弱」的观感。

两层叠加后，低频决定云的大块明暗，高频增加边缘碎屑感；层数越多通常越细腻，但片元成本也越高。
